## A. Project overview

**What it does.** Claude researches real-estate projects and writes them into an Excel workbook, with an optional ZIP of images. It then:

1. Validates the batch against the live master data, with no writes.
2. Imports the valid rows as **unpublished draft projects** in the My Property Fact database.

The import is asynchronous: Claude receives a job id and polls for the result.

**Why Next.js is the gateway.**

- The Spring Boot backend runs only on the developer's machine (`localhost:8005`), so it isn't reachable from the internet.
- The existing Next.js server already runs alongside it.
- Five small Next.js route handlers expose **only** the five Property Automation endpoints. They add a gateway key and per-IP rate limits, and forward each call unchanged to Spring Boot.
- There's no generic forwarding, and no access to login or any other backend API through these routes.

**How ngrok exposes it.**

- `ngrok http 3000` publishes the Next.js server at a temporary `https://…ngrok-free.dev` address.
- Claude calls `https://<ngrok-domain>/api/property-automation/...`.
- The Spring Boot port itself is **not** tunnelled.

```text
Claude
  |
  v
ngrok HTTPS URL        https://YOUR_NGROK_DOMAIN
  |
  v
Next.js API Proxy      /api/property-automation/*   (gateway key + rate limit, port 3000)
  |
  v
Spring Boot Property Automation APIs   http://localhost:8005/api/v1/integrations/claude/*
  |                                    (JWT + MANAGE_PROJECTS + allow-list + least privilege)
  v
MySQL Database (local `mypropertyfact`)   drafts only: projects.status = false
```

## C. Authentication

Every request needs **two different credentials**:

```http
X-Property-Automation-Gateway-Key: YOUR_GATEWAY_KEY
Authorization: Bearer YOUR_BACKEND_JWT
```

| | Gateway key | Backend JWT |
|---|---|---|
| Purpose | Stops random internet traffic at the Next.js layer before it reaches the backend | Identifies **which account** is calling. The backend authorizes that account. |
| Generated by | The developer: a long random secret in `my-property-fact/.env.local` (`PROPERTY_AUTOMATION_GATEWAY_KEY`) | The backend login, `POST http://localhost:8005/api/v1/admin-portal/auth/login`, using the integration account. This login is **not** exposed by the gateway. |
| Validated by | Next.js (`gateway.js`), constant-time comparison | Spring Boot (JWT signature and expiry, `MANAGE_PROJECTS`, allow-list, least privilege) |
| Lifetime | Until the developer changes it | **24 h** (`security.jwt.expiration-time=86400000` in dev) |
| Header | `X-Property-Automation-Gateway-Key` | `Authorization: Bearer …` |

**Gateway checks, in order:**

1. The gateway is configured. The key must be at least 24 characters; otherwise `503 GATEWAY_DISABLED`.
2. The per-IP failure lockout is not active.
3. The key is present and correct.
4. The per-IP rate limit is not exceeded.
5. A Bearer header is present, and the token has the structure of a JWT.

The request is then forwarded with **only** `Authorization`, `Content-Type` and `Accept`. Cookies and other client headers are not forwarded.

**Backend checks, in order:**

1. The JWT is valid and unexpired (`401`).
2. The account has `MANAGE_PROJECTS` (`403`).
3. The connector is enabled (`404`).
4. The email is in `CLAUDE_INTEGRATION_ALLOWEDEMAILS` (`403`).
5. The account has exactly the `MANAGE_PROJECTS` permission and is not a SUPERADMIN (`403 ACCOUNT_TOO_PRIVILEGED`).
6. Rate limit: 10 validate/import calls per minute per account (`429`).

**Getting a backend JWT (done by the developer on the local machine):**

```bash
curl -s -X POST http://localhost:8005/api/v1/admin-portal/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email":"<INTEGRATION_EMAIL>","password":"<INTEGRATION_PASSWORD>","dashboardUsername":"<INTEGRATION_DASHBOARD_USERNAME>"}'
# -> 200 {"token":"<BACKEND_JWT>","refreshToken":"…","expiresIn":86400000,"user":{…}}
```

The `token` value is the backend JWT. The developer hands Claude the gateway key and the JWT through a private channel. After 24 h, or on any backend `401`, a new JWT is needed.

Never write real keys, tokens or passwords into prompts, reports, files or logs.

## D. API reference

Common error body produced by the **gateway** (same shape as the backend's, plus `source`):

```json
{"timestamp":"2026-11-23T12:07:26.640Z","status":401,"error":"GATEWAY_KEY_MISSING","message":"Missing X-Property-Automation-Gateway-Key header.","source":"gateway"}
```

Error bodies produced by the **backend** pass through unchanged and have **no** `source` field, for example:

```json
{"timestamp":"2026-11-23T12:07:36.234435500Z","status":404,"error":"JOB_NOT_FOUND","message":"No job with id 00000000-0000-4000-8000-000000000000"}
```

Gateway errors that apply to every endpoint:

| Status | `error` | Cause |
|---|---|---|
| 401 | `GATEWAY_KEY_MISSING` | no `X-Property-Automation-Gateway-Key` header |
| 403 | `GATEWAY_KEY_INVALID` | wrong gateway key |
| 401 | `JWT_MISSING` | no `Authorization: Bearer …` header |
| 401 | `JWT_MALFORMED` | the token isn't a structurally valid JWT. The backend would answer such tokens with a 500, so the gateway refuses them first. |
| 429 | `RATE_LIMITED` | too many requests, or too many failed key attempts. Wait `Retry-After` seconds. |
| 405 | `METHOD_NOT_ALLOWED` | wrong HTTP method (header `Allow` names the right one) |
| 503 | `GATEWAY_DISABLED` | the gateway key or backend URL is not configured on the server |
| 503 | `BACKEND_UNAVAILABLE` | Spring Boot is not running or not reachable |
| 504 | `BACKEND_TIMEOUT` | Spring Boot did not answer in time: 10 min for uploads, 30 s for reads |
| 502 | `BAD_GATEWAY` / `BACKEND_ERROR` | other network failure, or a non-JSON backend error page (its body is hidden) |

Backend authorization errors that apply to every endpoint (passed through):

| Status | Body (`error` / `message`) | Cause |
|---|---|---|
| 401 | `UNAUTHORIZED` / "Authentication required (Bearer JWT from the admin login)" | JWT expired, revoked or invalid signature |
| 403 | `FORBIDDEN` / "MANAGE_PROJECTS permission is required" | account lacks `MANAGE_PROJECTS` |
| 403 | `FORBIDDEN` / "This account is not enabled for the Claude integration" | account not in the allow-list |
| 403 | `ACCOUNT_TOO_PRIVILEGED` | SUPERADMIN, or an account with more (or no) permission rows |
| 404 | `NOT_FOUND` / "Not found" | connector disabled (`CLAUDE_INTEGRATION_ENABLED` not `true`) |

> **Important: job URLs.** Backend responses contain `statusUrl` and `resultsUrl` values such as `/api/v1/integrations/claude/jobs/<jobId>`. These are **backend** paths. Always call the gateway paths instead: `/api/property-automation/jobs/<jobId>` and `/api/property-automation/jobs/<jobId>/results`. Take only the `jobId` from the response.

### D1. Validate properties (dry run)

| | |
|---|---|
| Purpose | Check a workbook (and optional ZIP) against the live database. **Writes nothing**: no job, project, builder or file. |
| Public URL | `POST https://YOUR_NGROK_DOMAIN/api/property-automation/properties/validate` |
| Backend mapping | `POST http://localhost:8005/api/v1/integrations/claude/properties/validate` |
| Headers | `X-Property-Automation-Gateway-Key`, `Authorization: Bearer`. `Content-Type: multipart/form-data; boundary=…` is set automatically by curl `-F` or any HTTP client building a form. |
| Path / query parameters | none |
| Body | `multipart/form-data` (not JSON) |

| Multipart field | Required | Rules |
|---|---|---|
| `excelFile` | yes | `.xlsx` / `.xls` whose content is a real workbook |
| `imagesZip` | no | `.zip` whose content starts with a ZIP signature |

The whole request is limited to **10 MB** through this gateway (see [K](#k-security-and-testing-limitations)).

```bash
curl -s -X POST "$BASE_URL/api/property-automation/properties/validate" \
  -H "X-Property-Automation-Gateway-Key: $GATEWAY_KEY" \
  -H "Authorization: Bearer $BACKEND_JWT" \
  -F "excelFile=@$EXCEL_FILE" \
  -F "imagesZip=@$IMAGES_ZIP"
```

**`200 OK`** returns a `ClaudeValidationReport`. A `200` does **not** mean the data is valid: read `valid`.

| Field | Meaning |
|---|---|
| `valid` | `true` only if there are no ERRORs, no duplicate rows, and at least one row |
| `importableRows`, `blockedRows`, `duplicateRows`, `totalRows` | row counts |
| `errorCount`, `warningCount` | issue totals |
| `workbook` | `filename, format, sheetName, sheetNames[], headerRow, firstDataRow, lastDataRow, dataRows, detectedHeaders[] (column, rawHeader, normalizedHeader, mappedTo, status), missingRequiredHeaders[], unknownHeaders[], unsupportedFields{}` |
| `zip` | only if a ZIP was sent: `filename, entries, images, extractedBytes, issues[]` |
| `workbookIssues[]` | sheet- or header-level issues |
| `rows[]` | `excelRow, sourceReference, projectName, builderName, cityName, reraNo, predictedSlug, status (VALID / BLOCKED / DUPLICATE_REVIEW_REQUIRED), existingProjectId, duplicateReasons[], newBuilder, builderId, amenitiesMatched[], floorPlans, locationBenefits, faqs, images[] (file, type, slot, width, height, format), errors[], warnings[], unappliedFields{}` |

Issue object: `{"severity":"ERROR|WARNING|INFO","code":"…","message":"…","excelRow":2,"column":"…","value":"…"}`. Only `ERROR` blocks.

| Status | Body | When |
|---|---|---|
| 200 | report | always for a readable request; check `valid` |
| 400 | `MISSING_PARAMETER` ("Required part 'excelFile' is not present."), `EXCEL_REQUIRED`, `EXCEL_EXTENSION`, `ZIP_EXTENSION`, `ZIP_INVALID` ("imagesZip is not a ZIP archive (content checked)") | bad upload |

- Call import only once `valid` is true, or when partial import is intended.

### D2. Import properties (create drafts, asynchronous)

| | |
|---|---|
| Purpose | Validate again and queue the valid rows for creation as **unpublished drafts** |
| Public URL | `POST https://YOUR_NGROK_DOMAIN/api/property-automation/properties/import` |
| Backend mapping | `POST http://localhost:8005/api/v1/integrations/claude/properties/import` |
| Headers | both credentials, plus a multipart `Content-Type` (automatic) |
| Path parameters | none |
| Query parameters | optional `batchName`, `dryRun`, `allowPartial`, `idempotencyKey`. The same four may instead be sent as multipart fields. Other query parameters are dropped by the gateway. |
| Body | `multipart/form-data` |

| Field | Required | Default | Notes |
|---|---|---|---|
| `excelFile` | yes | | as in validate |
| `imagesZip` | no | | as in validate |
| `batchName` | no | | label (stored up to 200 chars) |
| `dryRun` | no | `false` | `true` = validate only. Returns `200` and writes nothing. |
| `allowPartial` | no | `false` | `false`: any blocked or duplicate row refuses the whole batch. `true`: valid rows are imported and the others are recorded. |
| `idempotencyKey` | no | SHA-256 of the files | your own batch key. **Always send one**, so a retry after a timeout cannot create a second job. |

```bash
curl -s -X POST "$BASE_URL/api/property-automation/properties/import" \
  -H "X-Property-Automation-Gateway-Key: $GATEWAY_KEY" \
  -H "Authorization: Bearer $BACKEND_JWT" \
  -F "excelFile=@$EXCEL_FILE" \
  -F "imagesZip=@$IMAGES_ZIP" \
  -F "batchName=November batch" \
  -F "idempotencyKey=nov-batch-001"
```

**`202 Accepted`** (real example):

```json
{
  "jobId": "13ca8de5-0c78-49a9-8688-7df729876f7f",
  "status": "QUEUED",
  "dryRun": false,
  "message": "1 row(s) queued for draft creation. Poll statusUrl, then read resultsUrl.",
  "statusUrl": "/api/v1/integrations/claude/jobs/13ca8de5-0c78-49a9-8688-7df729876f7f",
  "resultsUrl": "/api/v1/integrations/claude/jobs/13ca8de5-0c78-49a9-8688-7df729876f7f/results",
  "validation": { "valid": true, "importableRows": 1, "…": "full validation report" }
}
```

**`200 OK`** for `dryRun=true` (real):

```json
{"dryRun":true,"message":"Dry run passed; nothing was written.","validation":{"valid":true,"importableRows":1,"…":"…"}}
```

When problems are found, the message is `"Dry run found problems; nothing was written."`.

**`409 Conflict`**: the same files or the same `idempotencyKey` were already accepted (real):

```json
{"error":"DUPLICATE_BATCH","message":"This batch was already submitted. Poll the existing job instead of resubmitting.","jobId":"13ca8de5-0c78-49a9-8688-7df729876f7f","status":"COMPLETED","statusUrl":"/api/v1/integrations/claude/jobs/13ca8de5-0c78-49a9-8688-7df729876f7f"}
```

| Status | When |
|---|---|
| 202 | queued; save `jobId` |
| 200 | `dryRun=true` |
| 409 `DUPLICATE_BATCH` | already submitted: poll the returned `jobId` |
| 422 (`status: "VALIDATION_FAILED"`) | blocking workbook or ZIP errors, no importable row, or blocked/duplicate rows without `allowPartial=true`. Same shape as 202, plus a message: "The workbook or ZIP has blocking errors; nothing was imported." / "No row can be imported; nothing was imported." / "Some rows have blocking errors or are duplicates; nothing was imported. Fix them, or resubmit with allowPartial=true." Nothing is created, and fixed files can be resubmitted. *(Taken from the backend code and docs; this gateway test didn't trigger it.)* |
| 503 `QUEUE_FULL` | backend queue (20 jobs) full: retry later |
| 400 / 401 / 403 / 404 / 413 / 415 / 429 / 5xx | as in validate |

**What Claude should do next:**

- On 202, store `jobId` and poll D3 every 3–5 s until the status is terminal.
- On 409, poll the returned `jobId`.
- On 422, read `validation`, fix the data, and resubmit.
- On a gateway `504` during import, the backend may still have accepted the batch. Resubmit with the **same** `idempotencyKey`: a `409` returns the existing `jobId`.

## E. Excel upload requirements

- **Template:** `mpf-claude-property-template.xlsx` (from D5). The reference workbook used to build the importer is `Property List-1 - Copy (1).xlsx`.
- **Sheet:** the **first** sheet is read (`Sheet1` expected). Other sheets are ignored, with a warning.
- **Layout:** row 1 holds the headers; one property per row from row 2; at most 500 rows. Headers are matched case- and whitespace-insensitively, and column order doesn't matter.
- **32 headers:**
  - `ID`, `BUILDER NAME`, `PROJECT NAME`, `PROPERTY TYPE NAME`, `PROJECT STATUS NAME`, `PROJECT CONFIGURATION`, `PROJECT LOCALITY`
  - `CITY NAME`, `STATE NAME`, `COUNTRY NAME`, `RERA NO`, `RERA WEBSITE`, `IVR NO`, `PROJECT PRICE`
  - `META TITLE`, `META DESCRIPTION`, `META KEYWORD`, `AMENITY DESCRIPTION`, `LOCATION DESCRIPTION`, `FLOOR PLAN DESCRIPTION`, `BUILDER DESCRIPTION`
  - `PROJECT Amenities`, `LOCATION ADVANTAGE`, `PROJECT WALKTHROUGH DESCRIPTION`
  - `Question 1`, `Answer 1` … `Question 4`, `Answer 4`
  - Optional extra: `PROJECT ABOUT SHORT DESCRIPTION`.
- **Required values (every row):** BUILDER NAME, PROJECT NAME, PROPERTY TYPE NAME, PROJECT STATUS NAME, CITY NAME, STATE NAME, COUNTRY NAME. Short text columns are limited to 255 characters (`VALUE_TOO_LONG`).
- **`ID`:** a reference only (`sourceReference`). It is never a database id and never used to update anything.
- **Master data must already exist** (nothing is created and nothing falls back):
  - **City** (`UNKNOWN_CITY`): must exist and belong to the given state.
  - **State** (`UNKNOWN_STATE`): must exist and belong to the given country.
  - **Country** (`UNKNOWN_COUNTRY`)
  - **Property type** (`UNKNOWN_PROPERTY_TYPE`)
  - **Project status** (`UNKNOWN_PROJECT_STATUS`)
  - Local values seen during testing: status `Completed`, `Ready To Move`, `New Launched`, `Under Construction`, `Ultra Luxury`, `Featured` (note: `New Launch` is **invalid**); type `Residential`, `Commercial`, `New Launches`; country `India`.
- **Amenities:** tokens separated by `_`, `|` or `,`; a `-` is read as a space. **Every token must match** an existing amenity, or the row is blocked (`UNKNOWN_AMENITY`, with a "did you mean" hint). For example, `Rainwater-Harvesting` is rejected and `Rain-Water-Harvesting` is accepted.
- **Builder:**
  - **Existing builder** (case- and space-insensitive match): it is used and never modified, and `BUILDER DESCRIPTION` is not written (it goes to `unappliedFields`).
  - **Unknown builder:** a **new builder** is created, with warning `NEW_BUILDER`, and the description is saved only for that new builder.
- **Duplicates:** a row matching an existing project by slug, RERA number, or name + builder + city becomes `DUPLICATE_REVIEW_REQUIRED` and is **never** written. Duplicates inside the workbook are errors. Existing projects are never updated.
- **LOCATION ADVANTAGE:** only `Place-Name-4.2-Km` or `Place Name (4.2 Km)` segments are stored. Prose is reported (`LOCATION_ADVANTAGE_UNPARSED`) and kept in `unappliedFields`.
- **FAQs:** each complete Question/Answer pair becomes an FAQ. A half pair blocks the row (`FAQ_INCOMPLETE`).
- **Validation workflow:** validate (D1) → fix → validate again → import (D2). The import validates again against the current database.

## F. ZIP and image requirements

- **File name:** `<Project-Key>_<Type>[_<anything>].<jpg|jpeg|png|webp>`.
  - Project key = PROJECT NAME with spaces replaced by `-`, matched by slug. For example, row "Example Heights" → `Example-Heights`.
  - Never put `_` inside the key.
  - Everything after the second `_` is ignored, so the `_My-Property-Fact` suffix is optional.
- **Types (one of each per project unless numbered):**

| Type token | Stored as | Resized to fit within | Max per project |
|---|---|---|---|
| `Logo` | project logo | 792 × 203 | 1 |
| `Thumbnail` | project thumbnail | 800 × 800 | 1 |
| `Location` / `LocationMap` | location map | 1200 × 800 | 1 |
| `Desktop-1`, `Desktop-2`, … (`DesktopBanner`) | desktop banners | 2508 × 1200 | many |
| `Mobile-1`, `Mobile-2`, … (`MobileBanner`) | mobile banners | 800 × 800 | many |
| `Gallery-1`, `Gallery-2`, … | gallery | 1600 × 1200 | many |

- **Numbering:** number repeating types *inside the token* (`Gallery-1`, `Gallery-2`). `X_Gallery_1.jpg` plus `X_Gallery_2.jpg` is **rejected** (`IMAGE_DUPLICATE_TYPE`), because both have the token `Gallery`.
- **Unknown tokens** such as `ProjectLogo` or `Brochure` are rejected (`IMAGE_UNKNOWN_TYPE`).
- **Formats:** JPEG, PNG and WEBP. The content must match the extension (`IMAGE_EXTENSION_MISMATCH`). GIF and BMP are refused.
- **Content checks:**
  - Magic bytes and a valid end marker are required, and the image must fully decode (`IMAGE_INVALID_CONTENT`, `IMAGE_CORRUPTED`).
  - Minimum side 100 px; at most 60 megapixels and 40 MB per image.
- **Resizing:** images are resized and re-encoded into the boxes above, the same as the admin importer. Smaller images are **upscaled** (warning `IMAGE_WILL_BE_UPSCALED`).
- **ZIP layout:**
  - Folders are optional. A folder, if used, must equal the project key (`IMAGE_FOLDER_MISMATCH`).
  - File names must be unique across the ZIP (`ZIP_DUPLICATE_FILE_NAME`).
  - `__MACOSX`, `.DS_Store` and `Thumbs.db` are ignored. Any other non-image file blocks the batch (`ZIP_UNEXPECTED_FILE`).
  - Path traversal is refused (`ZIP_UNSAFE_PATH`).
- **Errors:**
  - An image for a project that isn't in the workbook blocks the **batch** (`IMAGE_PROJECT_NOT_IN_WORKBOOK`).
  - A bad image whose name identifies a row blocks **that row**.
- **Core images:** if Desktop, Mobile or Thumbnail is missing, the row gets the warning `IMAGE_CORE_MISSING`. With no ZIP at all, every row gets the warning `NO_IMAGES`.

Example:

```text
properties_images.zip
└── Example-Heights/
    ├── Example-Heights_Desktop-1_My-Property-Fact.jpg
    ├── Example-Heights_Mobile-1_My-Property-Fact.jpg
    ├── Example-Heights_Thumbnail_My-Property-Fact.jpg
    ├── Example-Heights_Logo_My-Property-Fact.png
    ├── Example-Heights_Gallery-1_My-Property-Fact.jpg
    └── Example-Heights_Gallery-2_My-Property-Fact.jpg
```

## G. Claude automation workflow

1. **Get the template:** call D5 with `format=json` for the column rules, and with `xlsx` for the file.
2. **Research** each project from reliable sources: the developer's site, the state RERA portal and listings. Record the sources.
3. **Verify RERA** on the official state portal (for example `https://www.up-rera.in/`). If it can't be verified, leave `RERA NO` blank; this gives a warning, not a guess.
4. **Prepare the workbook:**
  - One row per project.
  - Exact master-data spellings for city, state, country, type, status and amenities.
  - Four complete FAQ pairs.
  - Factual descriptions about **that** project only.
5. **Prepare the ZIP** with the names in [F](#f-zip-and-image-requirements), keeping the request at 10 MB or less in total.
6. **Authenticate:** use the gateway key and backend JWT supplied by the developer. On a backend `401`, ask for a fresh JWT.
7. **Validate (D1).**
8. **Analyse** `valid`, every `ERROR`, the duplicate rows and the warnings.
9. **Correct** the data and repeat steps 7–8 until `valid: true`. Remove duplicates; never try to overwrite existing projects.
10. **Import (D2)** with a unique `idempotencyKey`.
11. **Save the `jobId`.**
12. **Poll the job status (D3)** every 3–5 s until it is terminal.
13. **Fetch the results (D4).**
14. **Verify** each row has `importStatus = CREATED_DRAFT`, `draft = true` and `verified = true`. Then report the draft ids and slugs, new builders, warnings and `unappliedFields` to the human reviewer. Publishing is a manual admin action.

**Validation success is not import success.**

- `valid: true` only means the data passed the checks at that moment.
- The import validates again, runs asynchronously, and can still produce duplicates (for example if someone created the project in the meantime) or failures.
- Only D4's per-row result confirms that a draft exists.

## H. Testing examples (copy-paste)

```bash
export BASE_URL="https://YOUR_NGROK_DOMAIN"        # or http://localhost:3000
export GATEWAY_KEY="YOUR_GATEWAY_KEY"
export BACKEND_JWT="YOUR_BACKEND_JWT"
export EXCEL_FILE="/path/to/properties.xlsx"
export IMAGES_ZIP="/path/to/properties_images.zip"
AUTH=(-H "X-Property-Automation-Gateway-Key: $GATEWAY_KEY" -H "Authorization: Bearer $BACKEND_JWT")

# 1. Template (JSON spec + xlsx download)
curl -s "$BASE_URL/api/property-automation/template?format=json" "${AUTH[@]}"
curl -s -o mpf-claude-property-template.xlsx "$BASE_URL/api/property-automation/template" "${AUTH[@]}"

# 2. Validate
curl -s -X POST "$BASE_URL/api/property-automation/properties/validate" "${AUTH[@]}" \
  -F "excelFile=@$EXCEL_FILE" -F "imagesZip=@$IMAGES_ZIP"

# 3a. Import dry run (writes nothing)
curl -s -X POST "$BASE_URL/api/property-automation/properties/import" "${AUTH[@]}" \
  -F "excelFile=@$EXCEL_FILE" -F "imagesZip=@$IMAGES_ZIP" -F "dryRun=true"

# 3b. Import (creates drafts) -> save jobId
curl -s -X POST "$BASE_URL/api/property-automation/properties/import" "${AUTH[@]}" \
  -F "excelFile=@$EXCEL_FILE" -F "imagesZip=@$IMAGES_ZIP" \
  -F "batchName=Test batch" -F "idempotencyKey=test-batch-001"
export JOB_ID="JOB_ID_FROM_RESPONSE"

# 4. Job status (repeat until COMPLETED / PARTIALLY_COMPLETED / FAILED / VALIDATION_FAILED)
curl -s "$BASE_URL/api/property-automation/jobs/$JOB_ID" "${AUTH[@]}"

# 5. Job results
curl -s "$BASE_URL/api/property-automation/jobs/$JOB_ID/results" "${AUTH[@]}"
```

Postman: use `Body → form-data`, with keys `excelFile` and `imagesZip` of type **File**. Don't set `Content-Type` manually; Postman adds the boundary.

## I. Errors and troubleshooting

| Status | Typical `error` | Meaning / fix |
|---|---|---|
| 400 | `INVALID_JOB_ID`, `INVALID_FORMAT` (gateway); `MISSING_PARAMETER`, `EXCEL_EXTENSION`, `ZIP_EXTENSION`, `ZIP_INVALID`, `EXCEL_REQUIRED` (backend) | Fix the request: field names are exactly `excelFile` / `imagesZip`, the extensions must match the content, and the jobId must be a UUID |
| 401 | `GATEWAY_KEY_MISSING`, `JWT_MISSING`, `JWT_MALFORMED` (gateway); `UNAUTHORIZED` (backend: JWT expired or invalid) | Send both headers. For a backend 401, get a new JWT (24 h lifetime). |
| 403 | `GATEWAY_KEY_INVALID` (gateway); `FORBIDDEN`, `ACCOUNT_TOO_PRIVILEGED` (backend) | Wrong gateway key, or an account that isn't the allow-listed integration account with exactly `MANAGE_PROJECTS` |
| 404 | `JOB_NOT_FOUND`, or `NOT_FOUND` "Not found" | Unknown jobId, or the connector is disabled on the backend (`CLAUDE_INTEGRATION_ENABLED`) |
| 405 | `METHOD_NOT_ALLOWED` | Use the method in the `Allow` header |
| 409 | `DUPLICATE_BATCH` | Already submitted: poll the returned `jobId` |
| 413 | `PAYLOAD_TOO_LARGE` (gateway), `FILE_TOO_LARGE` (backend) | The request is over 10 MB. Split the batch or shrink the images. |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | Send `multipart/form-data`, not JSON |
| 422 | import `VALIDATION_FAILED` | Read `validation`, fix the rows, resubmit (or use `allowPartial=true`) |
| 429 | `RATE_LIMITED` | Gateway: 60 req/min, 10 uploads/min, 10 failed key attempts/min per IP. Backend: 10 validate/import per minute per account. Wait `Retry-After` seconds. |
| 500 | `INTERNAL_ERROR`, `SUBMISSION_FAILED` (backend) | Unexpected backend error; report it. No stack traces are returned. |
| 502 | `BAD_GATEWAY`, `BACKEND_ERROR` | Network failure, or a non-JSON backend error |
| 503 | `BACKEND_UNAVAILABLE`, `GATEWAY_DISABLED` (gateway); `QUEUE_FULL` (backend) | Spring Boot isn't running, the gateway isn't configured, or the queue is full |
| 504 | `BACKEND_TIMEOUT` | The backend is too slow. For imports, resubmit with the same `idempotencyKey`. |

Common problems:

- **HTML instead of JSON:** the ngrok browser warning page appeared. Add the header `ngrok-skip-browser-warning: true`.
- **Every call returns 404 "Not found" with a valid JWT:** the backend wasn't started with `CLAUDE_INTEGRATION_ENABLED=true`.
- **`ACCOUNT_TOO_PRIVILEGED`:** the account is a SUPERADMIN, or an ADMIN without exactly one permission row (`MANAGE_PROJECTS`).
- **Validate returns 200 but `valid: false`:** this is normal. Read the issues.
- **Upload fails at around 10 MB:** both the gateway and the backend dev profile limit uploads to 10 MB (see K).
- **"connection refused" or 503:** start Spring Boot (J).

## K. Security and testing limitations

- **Temporary public access.** The ngrok URL is public for as long as the tunnel runs. Stop ngrok when testing ends. The URL changes on restart.
- **Gateway key** (Next.js) and **backend JWT** (Spring Boot) are independent; both are required on these routes. The gateway key is never sent to the backend, and neither credential is logged.
- **Abuse protection:**
  - Per-IP limits: 60 requests/min, 10 uploads/min, and 10 failed key attempts/min. A failure lockout also refuses correct keys until the window resets.
  - The backend adds 10 validate/import calls per minute per account.
  - The gateway limiter is in memory, so it resets when Next.js restarts.
- **Allow-listed surface only:**
  - Exactly five routes, with fixed backend paths, allow-listed query parameters and UUID job ids.
  - No generic forwarding, no login endpoint, and no cookies forwarded.
  - Backend `Set-Cookie` and `Server` headers are dropped.
  - Non-JSON backend error pages are replaced, so no stack traces or paths leak.
- **Existing rewrite (pre-existing, not part of this gateway).**
  - `next.config.js` already forwards **every** `/api/v1/*` path to the backend.
  - Through the ngrok URL, the whole backend API is reachable **without** the gateway key, including `/api/v1/integrations/claude/*` and the login endpoint.
  - Backend authentication still applies there: JWT, allow-list and least privilege.
  - Treat the gateway key as an extra layer on the documented routes, **not** as the only protection.
- **Upload size: 10 MB per request.**
  - Next.js 15.5 middleware (`src/middleware.js`, which matches every path) buffers request bodies only up to 10 MB (`experimental.middlewareClientMaxBodySize`).
  - The backend dev profile also sets `spring.servlet.multipart.max-request-size=10MB`.
  - The gateway therefore refuses larger requests with `413 PAYLOAD_TOO_LARGE` instead of forwarding a truncated file.
  - Raising the limit needs changes to existing files (the middleware matcher or `next.config.js`, plus the backend dev properties). These are **not** done.
- **Local testing database:**
  - Everything writes to the local `mypropertyfact` database on the developer's machine.
  - Never point `MPF_BACKEND_URL` at a staging or production backend for these tests.
- **Draft-only.**
  - Every created project has `projects.status = false`. This is verified by reading the database back (`draft: true`), and the public project API doesn't serve it.
  - Nothing is published automatically.
- **Existing projects are protected:**
  - Duplicates (slug, RERA, or name + builder + city) are never written.
  - Existing projects and existing builders are never modified.
- **No deployment.** This is a local testing setup: nothing was deployed, committed or pushed.
